## 1. 产品概述

### 1.1 一句话定位

> 美股 RTH 内的 **交易导航 Agent**：你在券商端握方向盘（自主下单）；系统综合环境与结构，仅在 **决策周期收盘**（V0 默认 3 分钟）后更新 **结构许可**（不操作 / 允许开 / 持有 / 减仓许可 / 结构失效），预警周期（V0 默认 1 分钟）只提示风险。不做 FSD 式自动交易。

工作流：**静态观察名单 → 决策周期扫描 → 许可变更提醒 → 持仓值守（手动标记）→ 收盘复盘（MFE/MAE）**。盘前简报与动态 in-play 见附 D 延期项。

**不服务**：开盘抢跑、新闻秒单、跟单喊单、代客下单、自动交易、替你算股数或止盈。

### 1.2 产品隐喻：导航 vs FSD

| 交易导航（本产品） | FSD / 自动驾驶（明确不做） |
| --- | --- |
| 方向盘在你手中：下单、仓位、止损由你在券商完成 | 系统下单、调仓、平仓 |
| 综合路况：Regime、时段、流动性、事件禁入、同簇风险 | 承诺最优路径或收益 |
| **路口提醒**：许可变更（允许开 / 持有 / 减仓许可 / 结构失效） | 「现在买/卖、买多少」 |
| **确认型路口**：决策周期收盘后才改许可；预警周期不改许可 | tick 抢黄灯 |
| 偏航后重新规划：作废/超时；禁入路段不开新路口 | 自动跟单、收益排名 |
| 行程复盘：MFE/MAE、今日几个路口、误报统计 | 用业绩证明比人强 |

**播报纪律**（导航隐喻落地）：路况平稳时 **少播报**（看板静默 + L0/L1）；仅在 **状态变化** 与 **L2+ 路口** 推送，避免「cheap 雷达」式刷屏。

**文案纪律（与原型同一套词，禁止分叉）**：

| 引擎状态 | 盘中大字 | 含义 |
| --- | --- | --- |
| `IDLE` | **不操作** | 在观察名单，无许可 |
| `ARMED` | **不操作** | 条件接近，决策周期尚未确认 |
| `TRIGGERED` | **允许开** | 空仓 + 决策周期确认；**不是**「买入 N 股」 |
| `HOLD` | **持有** | 已手动标记进场；值守，不是再开一笔 |
| `INVALID` / `EXPIRED`（有仓） | **减仓许可** | 结构收回；减不减、减多少在券商端 |
| `INVALID` / `EXPIRED`（无仓） | **结构失效** | 许可作废，不要当成反向开仓 |

禁止用「买入 / 卖出 / 追 / 市价」当大字。允许写清作废价、还剩几根。加仓必须另开许可，默认关。

**两段时钟**：预警格按预警周期更新（V0 默认 1 分钟）；上表大字只在 **决策周期收盘**（V0 默认 3 分钟，或时段总闸）时变。

### 1.3 与投研 Agent、通用 AI 的区别

继承投研的 **工作流自动化 + 规则先行 + 结构化输出 + 防幻觉**；从日级解读收窄为 **日内路口提醒**，且 **少做、可作废、可度量**。

| 维度 | 投研 Agent | 通用 AI | 本产品（导航） |
| --- | --- | --- | --- |
| 核心产出 | 异动解读、日报 | 自由问答 | **结构许可卡**（状态 + 作废价 + fact bundle） |
| 时间粒度 | 日/场次 | 无节奏 | **决策周期收盘**（V0 默认 3 分钟） |
| 执行 | 不涉及 | 不涉及 | **绝不代驾** |
| 成功标准（打磨期） | 溯源 | — | **少误报路口** + MFE/MAE 日志 |

### 1.4 使用者（分阶段）

**V0 个人打磨（当前）**

- 使用者：作者本人；单配置、单 watchlist / in-play
- 诉求：少乱做、统一失效标准、跨时区跟美股时仍按 **决策周期收盘** 确认
- 验证：盘后 5 分钟仪式 + 周度模板调参，**不以付费转化为 KPI**

**V1+ 产品化（暂缓）**：美股 5m 确认派日内交易者，见原文档扩展。

### 1.5 解决的核心痛点

1. 全天一套规则 → **时段总闸**（开盘/午盘/尾盘不同路况）
2. 形态过敏 → **确认型模板** + **EXPIRED**
3. 标的过载 → **当日 in-play**
4. 一簇多响 → **同簇合并**（同一路口只报一次主路）
5. 提醒当指令 → **结构许可 ≠ 委托**；无股数；风控仅引用自填参数

### 1.6 开仓扫描 vs 持仓值守（必须拆开）

两套动作表，禁止混在同一个大字里。

**开仓扫描（空仓）**

| 状态 | 盘中 | 5 分确认后可以写 | 不可以写 |
| --- | --- | --- | --- |
| IDLE / ARMED | 不操作 | 还差哪条条件 | 提前允许开 |
| TRIGGERED | 允许开 | 作废价、模板、量能事实 | 股数、市价、止盈 |
| INVALID / EXPIRED | 结构失效 | 为何作废 | 「反过来做空/做多」 |

**持仓值守（已标记进场）**

| 状态 | 盘中 | 5 分确认后可以写 | 不可以写 |
| --- | --- | --- | --- |
| HOLD | 持有 | 结构仍有效；作废价 | 默认「回踩加仓」 |
| INVALID / EXPIRED | 减仓许可 | 结构已坏；每档只提醒一次 | 平仓市价、股数 |

V0：持仓靠手动标记，每根决策 K 开始时重读标记。未标记则永远走开仓表，弱于 VWAP 的标的显示 **不操作**，不显示减仓许可。从 `IDLE` 标上且本根收在 VWAP 上 → **持有**，作废价取本根 RTH VWAP；收在 VWAP 下则仍为 **不操作**。已经失效且已标记 → **减仓许可**。

**V0 信道**：Telegram 推送许可变更 + `inbox/YYYY-MM-DD.jsonl` 全量归档；HTML 原型是 **核验台**（与日志同一套词），不是执行端。约束问答延后 V1.2，看板内不作为买卖入口。

## 3. 设计原则

1. **规则决定「许可是否变更」，LLM 决定「如何说清楚」** —— 无触发不生成；禁止创造股数/市价；盘中用词以 §1.2 表为准。
2. **每条提醒必须可作废 + 可过期**（失效 + EXPIRED）。
3. **Regime 初判 + 关键位破坏才改** —— 不每根决策 K 翻标签。
4. **时段优先于模板** —— 午盘等路段默认不开新路口。
5. **少即是多** —— 导航宁少报；不以「少漏单」为口号。
6. **永不代驾** —— 无 `place_order`；V0 不接券商；V1+ 若只读持仓须与下单隔离。

## 4. 整体架构

**V0 实现形态**（个人）：`cron/loop` + Python 规则引擎 + 本地 JSON/Markdown 日志 + Telegram；可选静态 HTML 看板。

```
┌──────────────────────────────────────────────────────────────┐
│  V0 交互：Telegram 许可变更 · inbox/*.jsonl · 复盘 MD · HTML 核验台 │
│  V1+ 再扩：多通道推送 · 约束问答（非买卖入口）                    │
├──────────────────────────────────────────────────────────────┤
│  会话编排：RTH 决策周期 Loop · 日历禁入 · 收盘 Recap          │
├──────────────────────────────────────────────────────────────┤
│  A 规则引擎：Regime / 时段 / 模板 / 分级 / 作废·超时 / 同簇合并 │
│  B 叙事层：fact bundle → 七段式卡 · schema 校验               │
├──────────────────────────────────────────────────────────────┤
│  数据：决策/预警 K · SPY · 板块 ETF · calendar.yaml · 价差门   │
└──────────────────────────────────────────────────────────────┘
```

**工作流**：

> 决策周期收盘 → 数据/延迟校验 → 时段总闸与日历禁入 → Regime（按需更新）→ 规则 → 合并 → 叙事 → 推送 & 归档

**事件打断**：`calendar.yaml` 禁入窗内不开新的「允许开」；LULD 隔离该标的；新闻只进附件，不参与触发。盘前 Brief 不在 V0 第一周。

## 5. 交易会话模型（美股）

| 阶段 | 美东 | 导航行为 |
| --- | --- | --- |
| 盘前 | 08:00–09:25（可配） | **路况简报**：Regime 初判、禁入、in-play；**不报路口** |
| 09:30–10:00 | 开盘定价 | 只记 ORB；**禁止** VWAP/回撤 L2+ |
| 10:00–11:30 | 主路窗口 | 已启用模板可发「允许开」 |
| 11:30–14:00 | 午盘嘈杂 | **默认禁止新开 L2+**；仅失效/值守 |
| 14:00–15:30 | 午后 | Regime 单边才允许新开 |
| 15:30–16:00 | 尾盘 | **停止新开** |
| 16:00+ | 盘后 | 行程复盘 |

**数据纪律**：延迟超阈不发 L2+；RTH VWAP 不含盘前；停牌/价差/LULD 跳过。

**周期**：V0 默认预警 1 分钟、决策 3 分钟。许可只在决策周期收盘时变。秒级只入桶，不改许可。换周期要升规则版本并重跑夹具。

## 6. 核心功能模块

> V0 必做标 **【V0】**；其余标版本。

### 模块 1：Regime 路况引擎 【V0】

| 输入 | 产物 | 用途 |
| --- | --- | --- |
| 盘前 SPY/QQQ | 开盘类型 `GAP_*` | Brief |
| 10:00 快照 | 主 Regime `TREND_*` / `RANGE` | 锁定至破坏 |
| SPY vs VWAP + OR | `REGIME_CHANGE` | 收盘确认后播报 |
| VIX 前收 | `VOL_*` 日级 | 急升仅收紧 cap |
| in-play 广度 | VWAP 上/下占比 | 过滤逆势 |
| 宏观/财报 | `EVENT_DAY` + 禁入 | 模块 6 |

**观察名单**（≤8）：V0 用手写 `watchlist.yaml`，盘中不自动换票。缺口、相对量、广度排序的动态 in-play 延期。流动性只做价差门，见开发文档 `spread_bps_max`。

### 模块 2：路口扫描与分级 【V0】

**流动性门**：价、成交额、价差阈值。延迟超阈、停牌、LULD：**静默**，不发新许可。每张卡标注 `delay_tier`。

**确认型模板**：

| ID | 摘要 |
| --- | --- |
| `TPL_VWAP_RECLAIM` | 10:00 后；双棒收 VWAP 上 + 量确认；失效/EXPIRED 见 §2 历史版 |
| `TPL_ORB` | OR 完成后；宽度过滤；回踩确认才 L2 |
| `TPL_PULLBACK` | Regime 单边 + 回撤确认 |

**分级**：L0 灰显 → L1 看板 → **L2 推送** → L3 板块同向（V0 可仅 L2）。

**同簇合并** 【V0】：**同一路口只报主标的**。

**状态机**（与 §1.2 盘中用词一一对应）：

```
IDLE → ARMED → TRIGGERED ─┬→（手动标记进场）HOLD → INVALID | EXPIRED
                          └→ INVALID | EXPIRED（未进场）
```

冷却后回到 IDLE。午盘/尾盘总闸：禁止新的 TRIGGERED；已有 HOLD 只走值守。

### 模块 3：结构许可卡【V0】

日志 / Telegram / HTML **同一字段**（展示可用人话，枚举留在数据里）：

1. `state`：IDLE / ARMED / TRIGGERED / HOLD / INVALID / EXPIRED  
2. `label`：不操作 / 允许开 / 持有 / 减仓许可 / 结构失效  
3. 标的、决策桶结束时间、`delay_tier`  
4. 触发事实（仅 fact bundle 数字）  
5. 作废价 + 到期还剩几根  
6. 通道：开仓扫描 | 持仓值守  
7. 尾注固定：「结构许可，非委托」

内部仍可存 `SETUP_TRIGGERED` 等枚举；**UI 与 Telegram 正文不展示引擎代号。**

### 模块 4：持仓值守 【V0 简化】

手动标记才进入 HOLD。自填 SL/时间止损仅作展示。结构反向或 Regime 恶化 → **减仓许可**，**每档一次**。不写平仓市价。未标记持仓的弱势股保持 **不操作**。

### 模块 5：期权 【延后 V1.2+】

V0 不接。远期仅注解，不升 L3。

### 模块 6：事件禁入窗 【V0 基础】

V0 用 `config/calendar.yaml` 列出禁入窗（可为空）。窗内不开新的「允许开」，持有与减仓许可继续。新闻解读不进触发条件。盘前 Brief 延期。

### 模块 7：频率治理

- **V0**：自设日上限 + 模板冷却（配置文件即可）  
- **V1+**：免费/Pro cap、多通道

### 模块 8：收盘复盘 【V0】

Regime 变更线、提醒列表、**MFE/MAE**、失效/超时比、自填 **听了做了/没做/误报**、次日 in-play 草稿。

### 模块 9：约束问答 【V1.2+】

### 模块 10：日志 【V0】

fact bundle、规则版本、推送时间；Markdown/CSV 本地落盘。

### 7.3 不代驾（硬性）

任何版本代码路径不含 OMS / `place_order`。

## 8. 用户流程

### 8.1 V0 个人流程（当前）

```
编辑 watchlist.yaml + 模板开关 + 自设日 cap
        ↓
盘前：脚本出 Brief（Telegram / 本地 MD）

        ↓

        ↓
INVALID / EXPIRED / REGIME_CHANGE / 时段总闸
        ↓
收盘：复盘 MD + 三分类标记 + 周度调参
```

```
注册 → 配置 → Brief 确认 → RTH 推送 → 复盘 → 参数商店 / 订阅
```

## 11. 技术实现要点

| 话题 | V0 建议 | V1+ |
| --- | --- | --- |
| 调度 | 本机单进程，对齐决策/预警桶收盘（ET） | 云 worker |

## 附 D：个人打磨版（V0 执行清单）

执行规格（周期、字段、夹具、阶段入口）以 [日内交易辅助agent-开发文档.md](日内交易辅助agent-开发文档.md) 为准。下面是仪式与成功定义，不再单独规定阈值。

### D.1 一周最小闭环

1. `config/watchlist.yaml`：符号、分组、名单上限  
2. `config/clocks.yaml`：预警/决策周期。`config/rules.yaml`：模板阈值、冷却、EXPIRED、误报统计参数。`config/calendar.yaml`：禁入窗，可为空  
3. `jobs/bar_loop.py` → 每根决策 K 收盘跑状态机 → `inbox/YYYY-MM-DD.jsonl`  
4. `jobs/backtest.py` → 同一 `bar_loop` 的回放  
5. `jobs/review.py` 与 `jobs/recap.py`（P3）→ 第 6 根 MFE/MAE 与日复盘稿  
6. `prompts/card.txt`：许可卡字段、禁止新增数字、禁止「买入/卖出」大字  
7. HTML 核验台与 jsonl **同一 state/label**；真实行情接入前只用 Demo 六态对齐  

**打磨期看板必须能点到的六态**：IDLE、ARMED、TRIGGERED（允许开）、HOLD、INVALID（减仓许可）、EXPIRED（结构失效）。日常密度以静默为主，禁止四只同时「有事做」。

### D.2 盘后 5 分钟仪式（建议坚持 4–8 周）

- 今日 L2+ 几条？是否该紧时段或关模板？  
- 任选最多 3 条路口标：**做了 / 没做 / 误报**  
- 每周日：看各模板 MAE 分布，调参或 `enabled: false`  

### D.3 V0 成功定义（非盈利）

- 导航让你 **少在午盘/假突破路口踩油门**（主观 + 误报率下降）  
- 规则与复盘可复述：**「为何今天响 / 为何没响」**  
- 达到后再考虑 V1 产品化与新功能，而非反过来  

### D.4 明确延期（打磨期不开发）

多用户、支付、完整免责声明 UI、短于 1 分钟的许可变更、盘前 Brief、动态 in-play、期权链、券商只读、约束问答当买卖入口、公开带单。
