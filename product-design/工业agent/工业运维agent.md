## 1. 产品概述

### 1.1 一句话定位

> 一款面向**中小制造工厂**的轻量化、主动式**设备预测性维护 AI Agent**：7×24 设备健康监控 + 故障提前预判 + 根因智能诊断 + 维保自动闭环 + 运维数据沉淀。**只做设备运维单一垂类，不做全厂数字化改造；纯工具赋能、合规可控。**

### 1.2 补齐的市场空白

| 现有方案 | 短板 | 本产品 |
| --- | --- | --- |
| 传统工业运维系统 | 被动记录、事后告警、部署重、成本高 | 主动预判 + 全闭环 + 轻量化 SaaS |
| 通用工业 AI 问答工具 | 被动聊天、无监控、无工单、幻觉严重 | 垂类规则约束 + Agent 自动化工作流 |
| 大厂工业智能平台 | 大而全、昂贵、周期长，中小企业用不起 | 小而精、1-3 天部署、按设备订阅 |

### 1.3 目标用户与适用场景

- **核心用户**：中小制造工厂的运维主管、设备管理员、车间负责人、厂长
- **适用设备**：3C 制造、汽配、五金、注塑、机械加工等离散制造的通用设备——电机、风机、泵体、空压机、流水线、机床
- **适用场景**：设备日常健康监控、故障提前预警、根因诊断、维保计划优化、运维复盘、设备资产健康管理

> **边界说明**：聚焦通用离散制造设备（有共性故障模型），流程工业（化工/冶金等高危连续生产）暂不涉及。

### 1.4 解决的核心痛点

1. **维保模式滞后** —— 事后维修导致突发停机，固定周期维保导致过度维护，均无法适配设备真实状态
2. **人工巡检低效** —— 漏检、错检、延时，无法捕捉早期微小退化信号
3. **根因定位困难** —— 依赖老工程师经验，新人上手难，故障经验无沉淀、同类问题反复发生
4. **运维数据零散** —— 台账、纸质单据、零散系统各自为政，无趋势分析、无复盘机制
5. **中小厂落地门槛高** —— 传统方案部署重、价格高、需要专业团队，中小企业预算与人才双缺

### 1.5 核心差异化

1. **主动 Agent 工作流，非被动问答**：7×24 自动扫描→识别异常→预判故障→生成报告→主动推送，无需人工触发
2. **垂类规则库 + AI 模型双驱动**：内置设备专属故障规则、损耗模型，时序 AI 与工业规则双向校验，输出可溯源、可核验
3. **轻量化极速落地**：无需整厂 MES/ERP 改造，对接 PLC、传感器、简易台账，**1-3 天完成部署**
4. **全闭环运维体系**：监控→预判→告警→诊断→派单→执行→复盘→沉淀，远超单一监控/告警类竞品
5. **标准化 SaaS 订阅**：摒弃工业项目制重交付，价格透明、续费稳定

## 3. 整体架构

四层轻量化架构，**无需自研大模型**，依托成熟数据接口 + 工业垂类规则库 + AI 时序模型构建壁垒。

```
┌─────────────────────────────────────────────┐
│  交互层：Web 管理后台 · 移动端小程序/APP        │
│         （后台精细管理 + 移动办公）              │
├─────────────────────────────────────────────┤
│  Agent 层：健康监控 · 预测诊断 · 预警推送 ·      │
│           维保复盘 · 运维知识库问答              │
├─────────────────────────────────────────────┤
│  规则引擎层（核心壁垒）：异常判定 · 故障分级 ·    │
│           根因诊断 · 模型校验（双向）             │
├─────────────────────────────────────────────┤
│  数据层：传感数据（振动/温度/电流/噪音/负载）·    │
│           时序运行数据 · 运维业务数据 · 标准知识库 │
└─────────────────────────────────────────────┘
```

**Agent 统一工作流**（固定闭环，无人值守）：

> 实时采集 → 数据清洗校验 → 异常规则判定 → AI 智能诊断 → 风险分级 → 预警推送 → 工单生成 → 执行跟进 → 复盘归档 → 知识沉淀

**数据层要点（多源适配，兼容老旧设备）：**

| 数据类别 | 内容 |
| --- | --- |
| 设备传感数据 | 振动、温度、电流、电压、噪音、运行负载、启停状态 |
| 时序运行数据 | 运行时长、启停频次、产能节拍、空载/负载时长 |
| 运维业务数据 | 历史故障记录、维保工单、零部件更换记录、巡检记录 |
| 标准知识库数据 | 设备手册、SOP 运维规范、零部件损耗标准、行业故障案例 |

## 4. 核心功能模块（V1.0 MVP）

### 模块 1：设备智能监控看板（基础底座）

替代人工巡检与静态台账，全厂设备可视化动态监控。

- **设备台账数字化**：批量录入/导入设备信息（型号、投产时间、位置、维保周期、零部件、责任人），形成电子资产台账
- **实时数据可视化**：温度、振动、电流、运行状态、负载率实时展示；单设备详情 + 全厂批量俯瞰
- **设备健康动态评分**：AI 综合多维度数据输出 0-100 健康分，四类状态标签（健康运行 / 轻微退化 / 潜在风险 / 高危故障）
- **异常实时标记**：超阈值、趋势异常数据自动标红，记录发生时间、持续时长、波动幅度
- **状态统计汇总**：全厂健康/异常/待维保设备数量分布看板

### 模块 2：故障预测与智能诊断 Agent（核心主打）

从事后告警升级为**事前预判、事中诊断、事后溯源**，支持剩余使用寿命（RUL）评估。

**识别三类异常信号**：瞬时数据超标、时序趋势漂移、周期性波动异常。

**结构化输出五段式（无幻觉、可溯源）：**

1. **异常事实**：异常数据、波动趋势、发生时段、涉及部位（绑定原始采集记录）
2. **故障预判**：可能故障类型、高发时段、剩余可用寿命，提前规避非计划停机
3. **根因拆解**：零部件磨损 / 参数漂移 / 过载运行 / 环境影响 / 操作不当分类定位
4. **风险分级**：轻微 / 一般 / 高危 / 紧急四级，明确影响范围、停机概率、产能损失预估
5. **维保建议**：标准化处理方案、临时管控措施、操作步骤、备件更换建议——无模糊化表述

### 模块 3：分级智能预警与工单闭环系统

从「单一告警、无跟进」升级为**预警→派单→执行→核验→归档全流程闭环**。

**预警规则（可自定义）：**

| 预警类型 | 触发逻辑 |
| --- | --- |
| 数据阈值预警 | 温度/振动/电流等超出安全阈值 |
| 趋势异常预警 | 数据持续漂移、缓慢退化——未超标但有潜在风险 |
| 寿命到期预警 | 零部件/设备服役临近生命周期上限，维保提醒 |
| 故障复发预警 | 同类故障短期重复出现，触发专项复盘 |

**工单闭环：**
- Agent 按风险等级自动生成工单，自动关联设备信息、故障原因、处理建议、所需备件
- 手动/自动指派运维人员，设置时限与优先级
- 运维人员上传处理过程、修复结果、备件更换记录
- **系统自动核验修复效果**：对比修复前后设备数据，确认问题彻底解决

**推送**：移动端弹窗、微信、站内、短信多级推送；高危故障紧急推送。

### 模块 4：AI 自动运维复盘 Agent（核心留存功能）

日/周/月自动生成全厂运维复盘报告，无需人工汇总。

1. **运行快照**：开机率、运行时长、健康度均值、异常次数汇总
2. **故障统计**：故障总数、分级分布、高频故障设备、高发故障类型排名
3. **维保汇总**：完成/逾期工单、备件消耗、维保成本统计
4. **根因复盘**：核心故障诱因汇总、反复出现的问题、运维短板分析
5. **优化建议**：维保周期调整、设备参数优化、巡检重点、备件储备优化
6. **风险预判**：下期高风险设备清单、重点监控设备、潜在故障预警

### 模块 5：设备运维知识库 Agent（轻资产核心能力）

打造工厂专属数字化运维智库，替代老工程师经验、解决经验流失。

- **智能文档解析**：自动录入设备手册、SOP、故障预案、图纸，结构化拆解
- **故障智能问答**：现场快速查询排查方法、参数标准、维保流程、备件型号
- **案例自动沉淀**：每次故障处理自动归档案例、方案、经验，形成专属案例库
- **知识智能推送**：针对高频故障、高风险设备主动推送运维知识与预防方案
- **防幻觉强约束**：无数据/案例支撑时如实反馈「无法确认」，不编造方案；所有回答绑定设备标准与历史案例

### 模块 6：设备资产与维保优化管理

- **维保周期智能优化**：按真实运行状态与损耗程度动态调整维保时间，避免过度维保与维保遗漏
- **备件智能管理**：关联故障频次与损耗周期，提醒库存不足/呆滞备件，优化储备成本
- **运维数据统计**：故障率、停机时长、维保成本、设备利用率量化统计

## 5. 核心产品规则（壁垒核心）

### 5.1 防幻觉强制规则

1. **数据溯源**：所有诊断、趋势分析、维保建议绑定原始采集数据、知识库原文、历史案例
2. **模糊信息降级**：数据不足、无法精准判定时不做主观推断，明确标注不确定性
3. **双校验机制**：AI 模型输出必须经工业垂类规则库二次校验，杜绝错误诊断

### 5.2 工业业务严谨性规则

1. 所有故障预判、维保建议均为**辅助参考**，不做绝对化判定，页面常驻风险提示
2. 设备操作、高危维保场景强制标注**「需专业人员现场核验执行」**
3. 全部数据留存可追溯，满足工厂生产运维台账留存、溯源管理要求

### 5.3 Agent 自动化工作流规则

固定闭环流程（采集→清洗→判定→诊断→分级→推送→工单→跟进→复盘→沉淀），全程无人值守。

## 6. 用户核心流程

```
管理员入驻 → 批量导入设备台账 → 对接传感/运行数据 → 配置阈值与维保规则
        ↓
Agent 启动 7×24 自动监控 · 动态更新健康评分
        ↓
识别异常/潜在故障 → 自动诊断分级 → 推送预警 + 生成维保工单
        ↓
运维人员接单 → 现场执行 → 上传处理记录 → 系统自动核验修复效果
        ↓
日/周自动复盘报告 → 故障案例归档 → 知识库沉淀
        ↓
运维人员知识库答疑 → 持续优化维保策略
```

## 附：MVP 落地优先级建议

| 优先级 | 模块 | 理由 |
| --- | --- | --- |
| P0 | 监控看板 + 故障预测诊断 Agent + 分级预警 | 构成核心价值闭环，验证「替人盯设备」主张；预警提前量是付费的核心理由 |
| P1 | 工单闭环 + 自动复盘 + 知识库 | 留存与粘性功能，形成运维数据资产沉淀 |
| P2 | 资产与维保优化管理 | 增值能力，依赖前期数据积累后才有效果 |

> **建议**：
> 1. **设备品类收窄**——MVP 聚焦 2-3 类通用设备（如电机/空压机/泵体，故障模型最成熟、振动温度数据最标准），跑通后再扩展品类
> 2. **数据接入先行验证**——中小厂最大的落地不确定性在数据侧（老旧 PLC 协议、无传感器设备），建议 MVP 前先做 5 家种子工厂的数据接入摸底，必要时提供「外置传感器套件」作为过渡方案
> 3. **诊断精度冷启动**——初期规则库以「阈值 + 趋势」保守判定为主，AI 预判能力随工单闭环数据积累逐步开放，避免早期误报损害信任
> 4. **渠道比产品关键**——中小工厂 SaaS 的获客依赖区域设备经销商/代理商体系，建议立项时同步评估渠道合作路径

## 附：idea 思路点评（整理时补充）

**思路的优点：**
- 「单一垂类 + 轻量化 + SaaS 订阅」切中小厂空白市场的定位逻辑清晰，与投研 Agent 同构（垂类规则库防幻觉 + Agent 自动化工作流 + 订阅商业化），方法论可复用
- 「预警-工单-核验-复盘-沉淀」闭环设计完整，复盘与知识库构成留存资产
- 双校验（AI 模型 × 工业规则）机制对工业场景的容错要求认知正确

**需要提前想清楚的两个问题（评审时大概率被问）：**
1. **数据冷启动**：预测性维护的精度依赖故障样本积累，新客户上线初期（无历史数据时）「提前 3-30 天预判」的承诺如何兑现？——建议口径改为「上线即有阈值/规则告警，预测能力随数据积累增强」
2. **价值验证方式**：如何证明「减少了非计划停机」？——需要在产品内建「停机损失 avoided」的量化统计（与投研 Agent 的预警回溯有效率统计同理），这是续费谈判的核心证据
